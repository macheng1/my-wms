# 管理端页面设计

## 使用目标

把需求转成清晰、可实现、符合管理后台习惯的页面结构和交互方案。

## 设计原则

- 管理端优先信息密度、可扫描、可重复操作，不做营销式页面。
- 以列表、筛选、表单、详情、状态操作、批量操作为核心。
- 优先使用 Semi UI 组件和项目已有组件，例如 `ProDataTable`、布局组件、上传组件。
- 页面文案要直接、短、可执行。
- 表格、表单、弹窗、确认提示和错误提示要完整。

## 工作流程

1. 确认页面入口：路由、菜单、权限码。
2. 设计页面区域：标题、工具栏、筛选区、表格区、操作列、弹窗/抽屉。
3. 设计字段展示：列、宽度、状态 Tag、日期格式、金额/数量格式。
4. 设计表单：字段、校验、默认值、禁用条件、提交后刷新。
5. 设计交互状态：loading、empty、error、提交中、防重复提交、删除确认。
6. 输出页面结构和组件拆分。

## Review 清单

- 是否能支撑日常管理操作？
- 是否有明确空状态和错误状态？
- 是否有权限控制和菜单入口？
- 表单校验是否和后端 DTO 对齐？
- 操作成功后是否刷新列表或更新局部状态？
