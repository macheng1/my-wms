# 前端 PRD 分析

## 使用目标

把产品需求转换成管理端可开发的前端任务，明确页面、路由、组件、接口、权限、交互状态和验收标准。

## 工作流程

1. 先读 PRD、现有页面、菜单配置、API 封装和相近业务模块。
2. 梳理用户操作路径：入口、列表、筛选、新增、编辑、详情、删除、状态切换、导入导出。
3. 拆出前端交付项：
   - 路由和菜单
   - 页面布局
   - 表格/表单/弹窗/抽屉
   - API 依赖
   - 权限码和可见性
   - loading/empty/error 状态
   - 表单校验和错误提示
4. 识别后端依赖：接口是否已有、DTO 是否明确、返回结构是否匹配。
5. 输出前端任务清单、风险点和验收标准。

## 输出建议

- 页面目标和用户路径。
- 路由与菜单变更。
- 页面模块拆分。
- 组件复用点。
- API 依赖清单。
- 权限和菜单码。
- 交互状态：加载、空数据、错误、提交中、禁用、确认二次弹窗。
- 联调风险和验收标准。
